the relevant permissions through the U.S. Stocks section. This is account/product
eligibility, not a separate Stock+ checkbox on the API-key page. API options
quotes additionally require an OPRA market-data card and whitelisting through
Bitget's business representative. [Launch access requirements](https://www.bitget.com/support/articles/12560603890720)
and [current options API docs](https://www.bitget.com/docs/catalog/stock-plus/options-quotes).

OBSERVED on 22 September 2026: a newly created post-upgrade HMAC key
authenticated successfully and a read-only UTA trade request succeeded. The
key exposes `uta_trade` read/write and intentionally has no wallet, withdrawal,
or transfer permission. Account settings/assets return `40014` because this key
does not have UTA management permission; Reverb records that distinction and
continues to block execution that requires verified settings.

OBSERVED: both the protected Stock+ quote and option-expiry routes return
`100001 — U.S. stock trading is not enabled for this account.` This definitively

HISTORICAL OBSERVATION on 21 September 2026: the prior HMAC key authenticated against

blocker, not a malformed key and not a Stock+ eligibility result. Stock+ and

## Calendar probe

**OBSERVED:** the configured public Nasdaq earnings endpoint accepts one `date`
query per day and returns rows under `data.rows`. A row can contain a date but
`time` can be `time-not-supplied`; it is not safe to turn that into a trade time
implicitly. Reverb therefore requires `config/calendar.json` to provide an
explicit `default_event_time_et` before a date-only event can schedule work.
The configured fallback is now explicitly `16:05 ET`; tool results label it
`configured_default_assumption` rather than source time. This is calendar
plumbing, not Bitget product evidence, and the reporting-time assumption remains
**ASSUMED** until verified from a first-party event source.

## Raw evidence and reproduction

`python3 scripts/probe.py capture` stores raw public HTTP response bodies and
appends their metadata to a hash-chained evidence ledger. Every run snapshots
the exact config. `python3 scripts/probe.py report` verifies hashes and computes
[measurements](measurements.md) from the most recent captured run. Failures stay
in the ledger and make capture exit nonzero; successful independent requests
are retained for diagnosis. No authenticated response or secret is published.

## Runtime safety blockers added after the initial gate

Even after the four feasibility answers are collected, Reverb will not approve
or submit a live trade until the post-event volatility scenario is calibrated,
the reaction order has an explicit side/quantity/limit price and separate
budget, and Bitget's runtime precision/minimum/price-band fields have been
validated for that symbol. These are deliberately fail-closed configuration
requirements, not defaults.
